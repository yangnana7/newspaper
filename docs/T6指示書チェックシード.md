## T6: イベント抽出パイプラインの例外ゼロ化 — 指示書 & DoDチェックシード

### 0. 目的

イベント抽出パイプライン（`scripts/ingest_events.py` と `event_extract.py`）が、異常入力や欠落値によって落ちることなく安定稼働し、必要なメトリクスが増加することを確認する。特に、`event_participant.role` の NOT NULL 制約や無効な日付に起因するエラーを再発させない。

### 1. 事前準備

1. **環境変数**（既定の DSN を必ず設定）

   ```bash
   export DATABASE_URL='postgresql://newsp@127.0.0.1:5432/newshub'
   export PGPASSWORD='＜newspのパスワード＞'
   ```
2. **サービス確認**
   systemd で `newshub-events.service` が有効になっていることを確認し、必要なら起動：

   ```bash
   sudo systemctl daemon-reload
   sudo systemctl restart newshub-events.service
   sudo systemctl status newshub-events.service
   ```

### 2. パイプライン検証手順

1. **スクリプト単体試験**
   `scripts/ingest_events.py` を限定件数で実行し、例外が出ないことを確認します。

   ```bash
   cd ~/newspaper
   .venv/bin/python -m scripts.ingest_events --limit 100
   # → 例: ingested_events=XX と出力すればOK
   ```

   * `ingested_events` が 0 でもエラーが出なければ良い。
   * ログに `psycopg.errors.NotNullViolation` や `DatetimeFieldOverflow` が出ていないか確認。

2. **invalid timestamp のガード確認**
   `tests/test_ingest_events_utils.py` で `_parse_ts` の単体テストが追加されているので、ローカルで pytest を実行し、年0の日時が None にフォールバックされるかを確認：

   ```bash
   pytest -q -k "test_parse_ts_handles_year_zero_and_utc"
   ```

3. **役割（role）のデフォルト確認**

   * DB側では `event_participant.role` に DEFAULT 'participant' が設定されていること（`db/migrations/2025-08-27_event_participant_role_default.sql` を適用済みなら `\d event_participant` で確認）。
   * アプリ側では `ingest_events.py` が参加者情報の欠落時に `role` を `"participant"` に設定していることを確認します。

4. **systemd サービス稼働とログ監視**

   * `journalctl -u newshub-events.service -n 50 --no-pager` で直近のログを閲覧し、`NOT NULL violation` などのエラーがないことを確認。
   * イベント取込が行われるたびに `ingested_events=N` の行が出力され、再起動ループが起きていないことを確認。

5. **メトリクス確認**

   * `/metrics` にアクセスし、`events_with_participants_total` や `entities_linked_total` が増加しているか確認します（新しいイベントが participants を含む場合）：

     ```bash
     curl -s http://127.0.0.1:3011/metrics | grep events_with_participants_total
     ```
   * `ingest_events` 実行前後で値が増えることを目視します。

### 3. DoDチェックシード（T6用）

* [ ] `scripts/ingest_events.py` を手動実行しても例外が発生しない（`ingested_events=N` が表示）。
* [ ] `_parse_ts` は年0・空文字列・無効日付を None にフォールバックし、pytest が通る。
* [ ] `event_participant.role` の NOT NULL 制約違反がログに現れない（DB側 DEFAULT/COALESCE が機能）。
* [ ] systemd の `newshub-events.service` が連続再起動せず、ジャーナルに致命的エラーがない。
* [ ] `/metrics` の `events_with_participants_total` がイベント取込のたびに増加する。
* [ ] MCP-First 方針継続（`/metrics`=HELP、`/`=404）。

### 4. 追加の注意・トラブルシュート

* **NULL role が再発する場合**：`scripts/ingest_events.py` の `COALESCE(%s,'participant')` を `COALESCE(NULLIF(%s,''),'participant')` に変更し、DBレベルで `ALTER TABLE event_participant ALTER COLUMN role SET DEFAULT 'participant'` を適用します。
* **日時エラーが出る場合**：`_parse_ts` のロジックを確認し、ISO 形式でないデータが入っていないか `event_extract` 側を調査します。
* **イベントが取り込めない**：`scripts/event_extract.py` が期待どおりにイベントを抽出しているか簡易テストを行い、入力テキスト中に "type\_id" や "participants" が含まれているか確認します。
