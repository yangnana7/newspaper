変更点（コード）:

  - --skip-existing（既定の欠損のみ投入と整合 / 明示受け入れ）
  - --sleep-ms（バッチ間スロットリング）
  - --max-retries（バッチ重試行・エクスポネンシャルバックオフ）
- tests/test_vector_filled_and_hnsw.py を追加。
  - chunk総数と、指定embedding_spaceのchunk_vec件数が一致することを検証。
  - chunk_vec 上にhnswインデックス（amname='hnsw'）が少なくとも1つ存在することを検証。
  - DBがないCIでは SKIP_DB_TESTS=1 でスキップ可能。

ローカル/本番での実施手順（要DB）:
1) 環境変数（固定値遵守）
   export APP_BIND_HOST=127.0.0.1 APP_BIND_PORT=3011
   export DATABASE_URL='postgresql://newsp@127.0.0.1:5432/newshub'
   export PGPASSWORD='＜newspのパスワード＞'
   export EMBED_SPACE=e5-multilingual   # serverと合わせる
   export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1

2) バックフィル（途中再実行安全）
   .venv/bin/python -m scripts.embed_chunks \
     --space "${EMBED_SPACE}" \
     --normalize \
     --batch 256 \
     --max-retries 5 \
     --skip-existing \
     --sleep-ms 25

3) 欠損0の確認（chunk:chunk_vec）
   psql "$DATABASE_URL" -Atc "WITH t AS (SELECT count(*) AS n FROM chunk), v AS (SELECT count(*) AS n FROM chunk_vec WHERE embedding_space='${EMBED_SPACE}') SELECT (SELECT n FROM t)-(SELECT n FROM v);"  # 0 を期待

4) HNSWインデックス（不足時のみ作成・ANALYZE）
   # e5-multilingual 向け cosine HNSW（既存があればスキップ）
   psql "$DATABASE_URL" -c "CREATE INDEX IF NOT EXISTS idx_chunk_vec_hnsw_e5_cos ON chunk_vec USING hnsw (emb vector_cosine_ops) WHERE embedding_space='${EMBED_SPACE}';"
   psql "$DATABASE_URL" -c "ANALYZE chunk_vec;"

5) EXPLAIN ANALYZE でインデックス使用確認（例: 近傍10件）
   psql "$DATABASE_URL" -c "\
   EXPLAIN (ANALYZE, COSTS, VERBOSE, BUFFERS, TIMING) \
   WITH q AS (SELECT emb FROM chunk_vec WHERE embedding_space='${EMBED_SPACE}' ORDER BY chunk_id DESC LIMIT 1) \
   SELECT d.doc_id \
   FROM chunk_vec v, q \
   JOIN chunk c ON c.chunk_id=v.chunk_id \
   JOIN doc d   ON d.doc_id=c.doc_id \
   WHERE v.embedding_space='${EMBED_SPACE}' \
   ORDER BY v.emb <=> q.emb \
   LIMIT 10;"

6) 回帰テスト（DBあり環境で）
   SKIP_DB_TESTS=0 pytest -q -k "vector_filled_and_hnsw"

注記:

- 既定のHNSW索引は schema_v2.sql に含まれるが、選定spaceと一致する索引がない場合のみ作成。
