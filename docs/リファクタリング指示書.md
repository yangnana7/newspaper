了解。いまの稼働は安定しているので“必須ではない”ですが、**非機能（保守性・再発防止）を上げる軽量リファクタ**はこのタイミングで入れる価値があります。ここでは、\*\*挙動を一切変えず（API/DBスキーマ非変更、CLI引数互換）\*\*に、CodexCLIへそのまま貼れる指示を用意しました。MCP-Firstと固定環境の原則は維持します（`/`は404、`127.0.0.1:3011` 固定、DBは`newshub`固定）。また、既定のデータ層・検索モデルはそのまま尊重します（doc/chunk/chunk\_vec 等の役割）。

# T7.5 “安全リファクタ”計画（非破壊）

## 0) ガードレール（破壊防止）

* **DB/HTTP互換**：DDL・テーブル名・カラム・APIエンドポイント/JSON形は一切変更しない。
* **CLI互換**：既存スクリプトの引数名・戻り値・ログ行（`ingested_events=… / linked_entities=…`）は維持。
* **環境固定**：`DATABASE_URL` は `/newshub` を含むURI、`APP_BIND_HOST=127.0.0.1`、`APP_BIND_PORT=3011` を強制（起動ガードは現行方針のまま）。
* **最小差分**：ファイル新設と関数抽出中心。**削除・改名はしない**（import壊しを避ける）。

## 1) 目的（このリファクタで直したいこと）

* **systemd再発防止**：実行パス揺れに強い“モジュール起動”へ統一（203/EXEC再発を予防）。
* **設定の一元化**：環境変数アクセスを型付き`settings`に集約（`/etc/default/mcp-news` と乖離させない）。
* **ログと例外の整流**：service監視のための**1行サマリ**を各ジョブで確実に出す。
* **テストで固定**：MCP-First/固定環境の**不変条件をpytestで網**にする（回帰を自動検出）。
